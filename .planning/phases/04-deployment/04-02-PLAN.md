  <name>Task 3: Set up UptimeRobot cold-start prevention monitor</name>
  <what-built>Both services are live: Vercel frontend + Render backend with correctly scoped CORS. The /health endpoint on Render returns {"status": "ok"} with no DB query — ideal for keep-warm pings.</what-built>
  <read_first>.planning/phases/04-deployment/04-RESEARCH.md</read_first>
  <action>
    The user must create an UptimeRobot HTTP monitor. Claude cannot access UptimeRobot.

    **Steps:**

    1. Go to https://uptimerobot.com and sign up for a free account (if not already registered)
    2. Click "+ Add New Monitor"
    3. Configure:
       - **Monitor Type:** HTTP(s)
       - **Friendly Name:** Gaucho Course Optimizer API
       - **URL:** `https://<your-render-service>.onrender.com/health`
       - **Monitoring Interval:** 5 minutes (free tier minimum — beats Render's 15-minute spin-down threshold)
    4. Click "Create Monitor"
    5. Verify the monitor shows "Up" status after the first check (may take up to 5 minutes)

    **Why 5 minutes:** Render free tier spins down services after 15 minutes of inactivity. A 5-minute ping interval ensures the service never reaches 15 minutes idle, preventing cold starts during active hours. The requirement (DEPLOY-03) says "every 10 minutes" which also works (10 < 15), but 5 minutes provides more safety margin and is the free tier minimum.
  </action>
  <how-to-verify>
    1. UptimeRobot dashboard shows the monitor with "Up" status (green)
    2. Wait 5-10 minutes and check that UptimeRobot has logged at least 2 successful pings
    3. Optionally: Check Render logs to confirm incoming GET /health requests from UptimeRobot IP
  </how-to-verify>
  <resume-signal>Confirm UptimeRobot monitor is active and showing "Up" status</resume-signal>
  <acceptance_criteria>
    - UptimeRobot monitor exists with type HTTP(s) targeting the Render /health URL
    - Monitor interval is 5 or 10 minutes
    - Monitor shows "Up" status
  </acceptance_criteria>
