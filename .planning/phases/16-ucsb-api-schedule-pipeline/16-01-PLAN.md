# Phase 16 Plan 01: UCSB API Client, Schedule Pipeline & Nightly Job

## Objective

Build the complete backend integration with UCSB's Academic Curriculums API and Quarter Calendar API. Create the API client module, ScheduledSection database model, instructor name matcher, sync pipeline, nightly refresh job, and expose schedule data through the professors endpoint.

## Context

- @.planning/phases/16-ucsb-api-schedule-pipeline/16-CONTEXT.md (API details, data model, matching logic)
- @db/models.py (existing SQLAlchemy models)
- @api/config.py (settings class)
- @api/schemas.py (Pydantic response schemas)
- @dashboard/queries.py (professor queries)
- @api/routers/courses.py (professors endpoint)
- @scheduler/jobs.py (existing APScheduler configuration)

## Tasks

### Task 1: UCSB API client module + name matcher
type="auto"

**Do:**
- Create `ucsb_api/__init__.py`
- Create `ucsb_api/client.py` with:
  - `UCSBApiClient` class using `requests` library
  - `fetch_classes(quarter_code, course_id)` - fetches sections from Academic Curriculums API
  - `fetch_quarter_calendar(quarter_code)` - fetches quarter info from Quarter Calendar API
  - Auth via `ucsb-api-key` header with UCSB_API_KEY from settings
  - Proper error handling and logging
- Create `ucsb_api/name_matcher.py` with:
  - `parse_ucsb_instructor(name)` - parses "CONRAD P T" into (last_name, initials)
  - `match_instructor_to_professor(parsed_name, professors)` - fuzzy matching using thefuzz
- Add `ucsb_api_key` to `api/config.py` Settings class
- Write tests in `tests/test_ucsb_client.py` with mocked API responses

**Done when:**
- Client can construct correct API requests with proper headers
- Name matcher correctly parses "CONRAD P T" into last_name="conrad", initials=["P", "T"]
- Name matcher finds correct professor via fuzzy last-name + initial matching
- All tests pass with mocked HTTP

### Task 2: Database model + schedule sync pipeline
type="auto"

**Do:**
- Add `ScheduledSection` model to `db/models.py` with all fields from CONTEXT.md
- Create `ucsb_api/schedule_sync.py` with:
  - `sync_course_sections(session, quarter_code, course_id)` - fetch + parse + match + store
  - Logic to strip padded course IDs from UCSB API
  - Upsert logic (update existing sections, insert new ones)
- Add `ScheduledSectionResponse` to `api/schemas.py`
- Write tests in `tests/test_schedule_sync.py` with mocked API + test DB

**Done when:**
- ScheduledSection model creates table in database
- Sync pipeline correctly fetches, parses instructor names, matches to professors, and stores sections
- Tests pass with mocked API and rollback DB sessions

### Task 3: API integration + nightly job
type="auto"

**Do:**
- Add `get_scheduled_sections(session, course_id, professor_ids, quarter_code)` to `dashboard/queries.py`
- Update `api/routers/courses.py` to include schedule data and `teaching_next_quarter` boolean in professors response
- Update `ProfessorRanking` schema with schedule fields
- Add nightly schedule refresh job to `scheduler/jobs.py`
- Write tests for the integrated endpoint and scheduler

**Done when:**
- Professors endpoint returns `scheduled_sections` and `teaching_next_quarter` per professor
- Nightly job registered in APScheduler
- All existing tests still pass
- New tests pass
