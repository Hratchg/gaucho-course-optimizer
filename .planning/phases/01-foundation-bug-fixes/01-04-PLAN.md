Per D-04: Create a weekly automated pg_dump GitHub Action that dumps the Neon DB and uploads as a workflow artifact. This protects against accidental data loss during active development.

Create `.github/workflows/weekly-pgdump.yml`:

```yaml
name: Weekly Neon DB Backup

on:
  schedule:
    # Every Sunday at 06:00 UTC
    - cron: "0 6 * * 0"
  workflow_dispatch: # Allow manual trigger

jobs:
  backup:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Install PostgreSQL client
        run: |
          sudo apt-get update
          sudo apt-get install -y postgresql-client

      - name: Dump Neon database
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
        run: |
          pg_dump "$DATABASE_URL" > data/gco_dump.sql
          echo "Dump size: $(du -h data/gco_dump.sql | cut -f1)"
          echo "Row check:"
          psql "$DATABASE_URL" -c "SELECT COUNT(*) AS gaucho_score_count FROM gaucho_scores;"

      - name: Upload dump as artifact
        uses: actions/upload-artifact@v4
        with:
          name: neon-backup-${{ github.run_id }}
          path: data/gco_dump.sql
          retention-days: 90
```

Key design decisions:
- Uses `schedule` with weekly cron (Sunday 06:00 UTC) per D-04
- Includes `workflow_dispatch` for manual trigger when needed
- Uses `secrets.DATABASE_URL` so the Neon connection string is never in code
- Uploads dump as a GitHub artifact with 90-day retention (not committed to repo -- avoids 13 MB commits weekly)
- Includes a row count check to verify the dump captured data
- Does NOT commit the dump back to the repo (would bloat git history with 13 MB weekly)
